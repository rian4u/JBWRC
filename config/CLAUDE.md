# CLAUDE.md — 공통 운영 지침
> **이 지침은 강제사항이다.** 선택적 참고가 아니며 모든 프로젝트·세션에 예외 없이 적용된다.
> 프로젝트 루트의 `CLAUDE.md`가 존재하면 해당 파일이 최우선이며, 충돌 시 프로젝트 지침이 이긴다.

---

## 1. 핵심 원칙

- **질문은 반드시 `AskUserQuestion` 도구 사용** — 텍스트로 번호 목록을 나열하지 않는다
- **두 가지 이상 해석이 가능한 경우 무조건 질문한다** — 추측하거나 임의로 선택하지 않는다
- **문서(기획서·설계서) 완료·승인 전 구현 절대 금지**
- **이전 단계 승인 없이 다음 단계 진행 금지**
- **구현 중 요구사항·전제가 변경되면 즉시 구현 중단 → 문서 업데이트·승인 → 재개**
- 되돌릴 수 없는 작업은 반드시 사전 확인

---

## 2. 사용자 프로필 (`~/.claude/docs/users/[name].md`)

매 프로젝트마다 반복되는 기본 환경 정보를 캐시하는 용도다.
프로필이 없으면 첫 세션에서 아래 항목만 `AskUserQuestion`으로 확인하고 생성한다.
이미 있으면 로드만 하고 넘어간다.

**기록 항목 (이것만):**
- 주 사용 OS·환경
- 선호 언어·프레임워크
- 기술 수준 (본인이 밝힌 범위 내에서)

기획서·설계서에 필요한 프로젝트별 상세 정보(사내망 제약, 배포 환경 등)는
프로필이 아니라 기획 단계(plan-conventions.md B-2)에서 질문한다.

---

## 3. 세션 시작

### 3-0. 설정 동기화 확인 (매 세션 최초 1회)

세션이 시작되면 다른 작업 전에 `AskUserQuestion`으로 GitHub 설정 동기화 여부를 묻는다:
- **"GitHub에서 최신 설정을 가져올까요?"**
  - 옵션: "가져오기 (pull)" / "건너뛰기"
- "가져오기" 선택 시: `/config-import` 스킬 실행
- "건너뛰기" 선택 시: 다음 단계(§3-1 또는 §3-2)로 진행

### 3-1. 프로젝트 문서가 없는 경우

① 프로젝트 CLAUDE.md 확인
② `docs/` 폴더 스캔 → 문서 없음 확인
③ **목적 질의** — AskUserQuestion으로 아래 항목 파악:
   - 무엇을 만드는가 (결과물)
   - 왜 만드는가 (목적·배경)
   - 누가 사용하는가 (대상)
   - 완료 기준이 무엇인가
   - 해석이 두 가지 이상 가능한 항목은 반드시 추가 질문
④ **역제안** — 기본 사항이 정리되면 사용자가 놓쳤을 요건을 적극적으로 제안한다
   - 예: "○○한 경우도 고려해야 할 것 같은데, 맞지 않나요?"
   - 사용자가 명시적으로 거절하거나 더 이상 없다고 할 때까지 반복
⑤ 답변을 바탕으로 **기획서 → 설계서 순서로 작성** (각 지침 문서 참조)
   - 기획서 → `docs/기획서.md`에 저장
   - 설계서 → `docs/설계서.md`에 저장
⑥ 양 문서 승인 후 `docs/진행내역.md` 생성 → 구현 시작

### 3-2. 프로젝트 문서가 있는 경우

① 프로젝트 CLAUDE.md 확인
② `docs/기획서.md`, `docs/설계서.md`, `docs/진행내역.md`, `docs/최종산출물.md` 정독
③ 관련 소스 코드 상세 파악 (구조·의존성·현재 상태)
④ 파악한 내용 요약 보고 후 작업 시작

## 4. 작업 흐름

```
목적 확인 → 기획서 작성·승인 → 설계서 작성·승인 → 구현 → 검증 → 완료 보고
```

### 단계별 필수 로드 문서

**해당 단계에 진입할 때 아래 문서를 로드하지 않은 상태로 작업을 시작하지 않는다.**

| 단계 | 진입 시 반드시 로드 |
|------|-------------------|
| 기획서 작성 | `~/.claude/docs/plan-conventions.md` |
| 설계서 작성 | `~/.claude/docs/design-conventions.md` |
| 구현 | `~/.claude/docs/engineering.md`, `~/.claude/docs/changelog-conventions.md` |
| 마일스톤 완료 | `~/.claude/docs/deliverable-conventions.md` |

### 구현 단계 실행 루프

코드·스킬 파일을 수정할 때마다 아래 루프를 **매 변경마다** 반복한다.
몰아서 처리하지 않는다 — 코드 1건 변경 → 진행내역 1건 기록이 한 세트다.

```
① 코드 작성/수정
② 즉시 `docs/진행내역.md`에 변경 기록 (changelog-conventions.md 참조)
   — ①과 ②는 항상 한 세트. ②를 건너뛰고 다음 ①으로 가지 않는다
③ 해당 마일스톤의 모든 원자 액션 구현이 완료되었는가?
   ├ 아니오 → ①로 돌아가 다음 원자 액션 구현
   └ 예 → /milestone-complete 스킬 실행 (검증·최종산출물·승인 절차)
④ 사용자 마일스톤 승인 후 다음 마일스톤의 ①로
```

- **변경 발생 시**: 구현 중단 → 영향받는 문서 재작성·승인 → 개발 재개

---

## 5. 검증 의무

구현이 완료되어도 아래가 충족되지 않으면 완료로 간주하지 않는다:
- 설계서에 명시된 검증 항목을 모두 통과했는가
- 검증 방법과 결과를 사용자에게 제시했는가

---

## 6. 임시 자산 관리

검증 목적으로 생성한 아래 항목은 **해당 검증이 끝나는 즉시 삭제**한다 (사용자 승인 불필요, 진행내역 기록 불필요):
- 임시 테스트·검증용 스크립트
- 스크린샷·캡처 파일
- 디버그용 더미 데이터·파일

---

## 7. 반복 요청 → 스킬 제안

동일하거나 유사한 작업을 **3회 이상** 요청받으면, 작업 수행 전 스킬 자동화를 제안한다.

---

## 8. 작업 완료 보고

작업이 끝났을 때 "완료"로 끝내지 않는다. 반드시 아래를 포함한다:
- 완료된 내용 한 줄 요약
- **사용자가 지금 해야 할 다음 행동 또는 의사결정 사항** (구체적으로)

예시: "설계서 작성 완료. 다음: 설계서를 검토 후 구현 시작 승인 여부를 알려주세요."
