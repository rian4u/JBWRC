# CLAUDE.md — 공통 지침
> 모든 프로젝트에 적용되는 핵심 원칙과 흐름. 작성 방법은 conventions.md에.

---

## 0. 적용 우선순위

1. 프로젝트 루트의 `CLAUDE.md` (있으면 최우선)
2. 이 파일 (`~/.claude/CLAUDE.md`)
3. 충돌 시 프로젝트 지침이 이긴다

---

## 1. 핵심 원칙

- **질문은 항상 `AskUserQuestion`** — 채팅창에 번호 목록을 텍스트로 나열하지 않는다
- **문서 완료 전 코드 작성 절대 금지** — 기획 → 설계 → 구현 순서를 지킨다
- **변경 발생 시 코드 먼저 수정하지 않는다** — 문서부터 플랜모드로 재작성 → 승인 → 개발
- **이전 단계 승인 없이 다음 단계 진행 금지**
- 모르면 모른다고 말한다. 추측하지 않는다
- 모호하면 명확해질 때까지 질문한다
- 되돌릴 수 없는 작업은 반드시 사전 확인

---

## 2. 세션 시작

① **프로젝트 CLAUDE.md 확인** → 있으면 최우선 로드
② **docs/ 스캔 + 사용자 프로필 로드**
   - `docs/` 폴더에 문서가 있으면 읽어서 맥락 파악
   - `~/.claude/docs/users/`에서 프로필 로드
   - 프로필 없으면 생성 → `conventions.md §2`
   - 프로필과 목적을 대조하여 부족한 정보만 추가 질의 → `conventions.md §2-3`
③ **목적 식별**
   - 기존 문서·소스로 파악 가능 → "작업 준비 완료" 보고
   - 파악 불가 → 사용자에게 목적 질의 (명확해질 때까지)

---

## 3. 프로젝트 작업 흐름

> **기획서** = 누가 · 무엇을 · 왜 — 질의응답으로 도출
> **설계서** = 어떻게 — 스스로 개발 가능한 수준까지 상세화

```
요구사항 구체화 → 기획서 작성 → 설계서 작성 → 구현
```

- 각 단계의 절차·템플릿 → `conventions.md §3~§6`
- 코드 작성 원칙 → `engineering.md`
- 변경 발생 시 → 코드 중단 → 문서 플랜모드 재작성 → 승인 → 개발 재개
  → `conventions.md §9`

---

## 4. 참조 문서

| 분류 | 문서 | 경로 | 로드 시점 |
|------|------|------|---------|
| 글로벌 | 사용자 프로필 | `~/.claude/docs/users/[name].md` | 세션 시작 |
| 글로벌 | 문서 작성 지침 | `~/.claude/docs/conventions.md` | 문서 작업 시 |
| 글로벌 | 개발 원칙 | `~/.claude/docs/engineering.md` | 코드·설계 시 |
| 프로젝트 | 기획서 | `docs/plan.md` | 세션 시작 + 편집 필요 시마다 |
| 프로젝트 | 설계서 | `docs/design.md` | 세션 시작 + 편집 필요 시마다 |
| 프로젝트 | 진행상황 | `docs/progress.md` | 세션 시작 + 편집 필요 시마다 |
| 프로젝트 | 의사결정 로그 | `docs/decisions/*.md` | 의사결정 시 |

> 각 문서는 해당 시점에만 읽는다. 세션 시작 시 전부 로드하지 않는다.

---

## 5. 기타 운영

- **스킬**: 반복 작업 감지 시 스킬화 제안 / 중복 감지 시 병합·조정 선택
- **파일 정리**: 테스트 파일은 종료 즉시 삭제 (확인 불필요)
- **세션 종료**: 진행상황 문서 갱신, 테스트 파일 삭제
