## 2. 문서 분류

### 글로벌 지침 (모든 프로젝트 공통, `~/.claude/docs/`)

| 문서 | 목적 | 로드 시점 |
|------|------|---------|
| `CLAUDE.md` | 전체 운영 규칙, 작업 흐름, 단계별 필수 문서 지정 | 매 세션 시작 |
| `plan-conventions.md` | 기획서를 어떻게 작성하는가 | 기획서 작성 단계 |
| `design-conventions.md` | 설계서를 어떻게 작성하는가 | 설계서 작성 단계 |
| `engineering.md` | 코드를 어떻게 작성하는가 | 구현 단계 |
| `changelog-conventions.md` | 진행내역을 어떻게 기록하는가 | 구현 단계 |
| `deliverable-conventions.md` | 최종산출물을 어떻게 작성하는가 | 마일스톤 완료 시 |

### 프로젝트 산출물 (프로젝트별, `docs/`)

| 문서 | 목적 | 생성 시점 |
|------|------|---------|
| `plan.md` | 무엇을, 왜, 어떤 도구로 만드는가 | 기획 단계 |
| `design.md` | 어떻게, 무엇을 통해 구현하는가 | 설계 단계 |
| `진행내역.md` | 변경 이력 + 아이데이션 (롤백 참고용) | 구현 시작 시 |
| `최종산출물.md` | 현재 완성 상태 (인수인계용) | 첫 마일스톤 완료 시 |
| `decisions/*.md` | 의사결정 근거 기록 | 결정 발생 시 |

## 3. 작업 흐름과 문서 관계

```
┌─────────────────────────────────────────────────────────────┐
│                        작업 흐름                             │
│                                                             │
│  ① 목적 확인                                                │
│     │                                                       │
│     ▼                                                       │
│  ② 기획서 작성·승인  ◀── plan-conventions.md                  │
│     │                     산출물: docs/plan.md                │
│     ▼                                                       │
│  ③ 설계서 작성·승인  ◀── design-conventions.md                │
│     │                     산출물: docs/design.md              │
│     ▼                                                       │
│  ④ 구현             ◀── engineering.md                       │
│     │                    changelog-conventions.md            │
│     │                                                       │
│     │  ┌─────────────────────────────────┐                  │
│     │  │ 구현 기간 중 지속 활동            │                  │
│     │  │                                 │                  │
│     │  │ - 코드 변경 → 진행내역.md 기록    │                  │
│     │  │ - 아이디어 → 아이데이션 섹션 기록  │                  │
│     │  │ - 변경 발생 → 문서 수정·승인·재개  │                  │
│     │  └─────────────────────────────────┘                  │
│     │                                                       │
│     ▼                                                       │
│  ⑤ 검증 (설계서 D섹션 기준)                                   │
│     │                                                       │
│     ▼                                                       │
│  ⑥ 최종산출물 갱신   ◀── deliverable-conventions.md           │
│     │                     산출물: docs/최종산출물.md            │
│     ▼                                                       │
│  ⑦ 마일스톤 완료 승인                                         │
│     │                                                       │
│     ├─ 다음 마일스톤 있음 → ④로 복귀                           │
│     └─ 전체 완료 → 완료 보고                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```
plan-conventions.md ──생성──▶ docs/plan.md
        │                         │
        │                         │ (원자 액션 입력)
        ▼                         ▼
design-conventions.md ──생성──▶ docs/design.md
        │                         │
        │                         │ (검증 체크리스트 입력)
        ▼                         ▼
engineering.md ────────────▶ 소스코드 (src/)
        │                         │
        │                         │ (변경 발생)
        ▼                         ▼

                                  ▼

```

## 5. 변경 시 영향 전파 규칙

```
요구사항 변경 발생
       │
       ▼
┌──────────────┐     ┌──────────────┐
│ plan.md 수정  │────▶│ design.md    │
│ (기획서)      │     │ 영향 확인·수정 │
└──────────────┘     └──────┬───────┘
                            │
              ┌─────────────┼─────────────┐
              ▼             ▼             ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ 소스코드  │ │진행내역   │ │decisions/│
        │ 수정     │ │[변경] 기록│ │사유 기록  │
        └──────────┘ └──────────┘ └──────────┘
```

### 설계서 변경 → 기획서 영향 판단 기준

| 변경 유형 | 기획서 영향 |
|---------|-----------|
| 구현 방식 변경 (동일 입출력) | 없음 |
| 기술 스택 변경 | 있음 |
| 인터페이스 변경 (입출력 변경 시) | 있음 |
| 원자 액션 추가/삭제 | 있음 |
| 오류 처리 추가 | 없음 |

## 7. 미확정 항목 흐름

```
기획서 (plan.md)
  │
  │ [미확정] 태그
  │ 결정 시점 명시
  │
  ├─ 결정 시점 = "설계 단계 전" → 기획 단계에서 해소
  │
  └─ 결정 시점 = "구현 단계 전" 등
       │
       ▼
  설계서 (design.md)
    │
    │ [미확정-기획이관] 태그로 수용
    │ 해당 원자 액션 구현 진입 전까지 해소
    │
    └─ 구현 진입 시점에 미해소 → 해당 액션 구현 불가
```

## 8. 아이디어 채택 흐름

```
구현 중 아이디어 발생
       │
       ▼
  진행내역.md 아이데이션 섹션에 [대기] 기록
       │
       ▼
  ┌────┴────┐
  │ 판단    │
  └────┬────┘
   입출력    입출력/범위
   불변      변경
   ▼         ▼
 [범위 내   [요구사항
  최적화]    변경]
   │         │
   ▼         ▼
 설계서     구현 중단
 해당 액션  → 기획서 수정
 수정       → 설계서 수정
   │         │
   ▼         ▼
 사용자     사용자
 승인       승인
   │         │
   └────┬────┘
        ▼
  [채택] → 변경 로그에 연결
```
