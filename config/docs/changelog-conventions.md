# changelog-conventions.md — 진행내역 관리 지침
> 로드 시점: 구현 시작 시 및 코드·스킬 변경 시마다
> 최종 수정일: 2026-03-25

---

## 진행내역이란 무엇인가

진행내역(`docs/진행내역.md`)은 실제 코드·스킬 변경이 발생할 때마다
**언제, 왜, 무엇을** 기록하여 추후 **롤백 가능한 수준의 이력**을 남기는 문서다.

기존 `progress.md`의 현재 상태 추적 역할을 통합하며, `progress.md`를 대체한다.

추가로, 구현 중 떠오르는 아이디어를 **아이데이션 섹션**에 기록하고
채택·배제 여부를 추적하여 의사결정 이력을 보존한다.

---

## 1. 생성 시점

구현 단계에 진입할 때 템플릿으로 초기 생성한다.
기획서·설계서 단계에서는 생성하지 않는다.

---

## 2. 기록 대상

아래에 해당하면 **반드시** 기록한다:

| 대상 | 예시 |
|------|------|
| 코드 수정 | 파일 생성·수정·삭제, 함수 추가·변경, 의존성 변경 |
| 스킬 수정 | SKILL.md 수정, 스킬 파일 추가·변경·삭제 |
| 설정 변경 | settings.json, CLAUDE.md, 지침 문서 수정 |
| 구조 변경 | 디렉토리 구조 변경, 파일 이동·리네임 |

아래는 기록하지 **않는다**:
- 임시 테스트·검증 파일 (생성 즉시 삭제되는 것들)
- 문서 오탈자 수정

---

## 3. 기록 상세도 기준

변경의 규모에 따라 기록 수준을 조절한다.

| 규모 | 판단 기준 | 기록 수준 |
|------|---------|---------|
| **소** | 단일 파일의 부분 수정, 1~2줄 변경 | 한 줄 요약 + 변경 파일명 |
| **중** | 여러 파일 수정, 함수 추가·변경, 로직 변경 | 변경 사유 + 변경 파일 목록 + 핵심 변경 내용 요약 |
| **대** | 구조 변경, 새 기능 전체 구현, 대규모 리팩토링 | 변경 사유 + 변경 전/후 상태 + 변경 파일 상세 + 롤백 절차 |

**"대" 규모 판단 기준:**
- 3개 이상 파일에 걸친 연쇄 변경
- 기존 동작 방식이 달라지는 변경
- 되돌리려면 여러 단계가 필요한 변경

---

## 4. 아이데이션 섹션

구현 중 떠오르는 개선 아이디어, 추가 기능 제안, 리팩토링 후보 등을 기록한다.

**기록 규칙:**
- 아이디어가 발생하면 `## 아이데이션` 섹션에 즉시 기록
- 각 항목에 발생일, 내용, 관련 기능을 기재
- 상태를 관리한다: `[대기]` → `[채택]` / `[배제]`

**채택 전 판단 기준:**

| 구분 | 판단 기준 | 절차 |
|------|---------|------|
| 범위 내 최적화 | 기획서의 기존 원자 액션 입출력이 변하지 않고, 구현 방식만 개선 | 설계서 해당 액션 수정 → `AskUserQuestion`으로 사용자 승인 → 구현 재개 |
| 요구사항 변경 | 원자 액션 추가/삭제, 입출력 변경, 범위 변경 | CLAUDE.md §4 적용: 구현 중단 → 기획서부터 수정 → 승인 → 재개 |

**상태 전환 시:**
- `[채택]`: 위 판단 기준에 따라 필요한 문서 수정·승인 후, 구현 시작 시 해당 항목을 변경 로그에 연결하고 아이데이션에서 상태를 `[채택] → 변경 로그 YYYY-MM-DD 참조`로 갱신
- `[배제]`: 배제 사유를 기재하고 상태를 `[배제] — 사유: ...`로 갱신
- **삭제하지 않는다** — 상태만 변경하여 의사결정 이력을 보존

---

## 5. 업데이트 규칙

- 코드·스킬 수정이 발생하면 **해당 수정 직후** 변경 로그에 기록한다 (나중에 몰아쓰기 금지)
- `최종 수정일`은 매 기록 시 갱신
- `현재 상태` 섹션은 변경 로그 기록 시 함께 갱신
- 변경 로그는 **최신순**(위가 최신)으로 작성
- 기존 변경 로그 항목은 수정하지 않는다 — 보정이 필요하면 새 항목으로 기록

---

## 6. 템플릿

```markdown
# 진행내역 — [프로젝트명]
> 최종 수정일: YYYY-MM-DD

## 현재 상태
- 전체 진행률: [단계명] (예: 기획 완료 / M1 구현 중 / 검증 단계)
- 블로킹 이슈: (없음 또는 이슈 내용)
- 다음 할 일: (1~3개)

## 변경 로그

### YYYY-MM-DD — [변경 제목]
- **규모**: 소 / 중 / 대
- **사유**: 왜 이 변경을 했는가
- **변경 내용**:
  - `파일경로`: 변경 내용 요약
  - `파일경로`: 변경 내용 요약
- **영향 범위**: 이 변경으로 달라지는 동작 (중·대 규모 시)
- **롤백 절차**: (대 규모 시 필수)
  1. 되돌리려면 어떤 순서로 무엇을 해야 하는가
  2. ...
- **관련**: [기획서 요구사항 번호 또는 마일스톤]

---

### YYYY-MM-DD — [변경 제목]
...

## 아이데이션

| # | 발생일 | 아이디어 | 관련 기능 | 상태 |
|---|--------|---------|---------|------|
| I-01 | YYYY-MM-DD | 아이디어 내용 | 관련 기능명 | [대기] |
| I-02 | YYYY-MM-DD | 아이디어 내용 | 관련 기능명 | [채택] → 변경 로그 YYYY-MM-DD 참조 |
| I-03 | YYYY-MM-DD | 아이디어 내용 | 관련 기능명 | [배제] — 사유: ... |
```

## 7. 이 지침 파일의 업데이트 조건

| 트리거 | 설명 |
|--------|------|
| 기록 운영 문제 | 이 지침으로 해결 안 되는 기록 상황이 2회 이상 반복 |
| 사용자 피드백 | 기록 품질·형식에 대한 방향 수정 요청 |
