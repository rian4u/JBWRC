# deliverable-conventions.md — 최종산출물 관리 지침
> 로드 시점: 마일스톤 완료 시 및 구현 단계 완료 시
> 최종 수정일: 2026-03-25

---

## 최종산출물이란 무엇인가

최종산출물(`docs/최종산출물.md`)은 프로젝트의 **현재 완성 상태**를
인수인계 관점에서 문서화한 것이다.

개발에 참여하지 않은 사람이 이 문서만 읽고
프로젝트의 목적, 사용법, 구조, 동작 흐름을 **즉시 파악**할 수 있어야 한다.

**스냅샷이 아니다** — 과거 이력이 아닌 **지금 이 프로젝트가 무엇인지**를 기술한다.

---

## 1. 생성 및 업데이트 시점

**마일스톤 완료 절차:** 검증 체크리스트 전체 통과 → 최종산출물 작성/갱신 → `AskUserQuestion`으로 마일스톤 완료 승인 → 다음 마일스톤 진행

| 시점 | 행동 |
|------|------|
| 첫 마일스톤 완료 시 | 첫 버전 작성 |
| 이후 마일스톤 완료 시 | 전체 문서를 현재 상태 기준으로 갱신 |
| 구현 단계 전체 완료 시 | 최종 갱신 |
| 구조 변경 시 | 폴더 구조, 스킬 구조 섹션 갱신 |

기획서·설계서 단계에서는 생성하지 않는다.

업데이트 시 **전체 문서를 현재 상태 기준으로 재작성**한다.
이전 버전과의 차이를 표시하지 않는다 — 항상 최신 상태만 반영한다.

## 2. 필수 섹션

| 섹션 | 내용 | 작성 기준 |
|------|------|---------|
| 목적 | 프로젝트가 무엇이고 왜 존재하는가 | 기획서 개요 기반, 비개발자도 이해할 수 있는 언어 |
| 사용자 가이드 | 설치, 실행, 주요 사용법 | 처음 접하는 사용자가 따라할 수 있는 단계별 안내 |
| 폴더 구조 | 전체 디렉토리 트리 + 각 폴더·파일의 역할 | 실제 파일 시스템과 100% 일치 |
| 스킬 구조 | 스킬 목록, 각 스킬의 역할, 트리거 조건, 계층 관계 | 스킬이 있는 프로젝트만 해당 (없으면 `(해당 없음)`) |
| 기능 및 파이프라인 | 주요 기능 목록 + 전체 동작 흐름 도식화 | 아래 §3 참조 |

## 3. 파이프라인 도식화 규칙

전체 프로젝트의 동작 흐름을 **텍스트 다이어그램**으로 작성한다.

**포함해야 할 내용:**
- 사용자 입력 → 처리 단계 → 최종 출력의 전체 흐름
- 각 단계에서 어떤 모듈·스킬·파일이 관여하는지
- 분기점과 조건이 있으면 표시
- 외부 시스템 연동 지점

**작성 형식 예시:**
```
[사용자 입력]
     │
     ▼
┌─────────────┐
│  단계 1      │ ← 담당: module_a.py
│  처리 내용    │
└──────┬──────┘
       │
       ▼
  ┌────┴────┐
  │ 조건 분기 │
  └────┬────┘
   Y   │   N
   ▼       ▼
[단계 2a] [단계 2b]
   │       │
   └───┬───┘
       ▼
[최종 출력]
```

복잡한 프로젝트는 **전체 개요 파이프라인 + 세부 파이프라인**으로 분리한다.

## 5. 이 지침 파일의 업데이트 조건

| 트리거 | 설명 |
|--------|------|
| 문서 운영 문제 | 이 지침으로 해결 안 되는 상황이 2회 이상 반복 |
| 사용자 피드백 | 문서 품질·형식에 대한 방향 수정 요청 |
| 새 섹션 필요 | 인수인계 시 추가 정보가 필요한 경우 |
