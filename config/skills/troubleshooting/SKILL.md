# Troubleshooting Skill

에러가 발생하거나 특수한 방법으로 처리에 성공한 경우 이 스킬을 따른다.

---

## 1단계: 에러 발생 시 — 먼저 기존 이력 확인

docs/troubleshooting.md 파일이 존재하면 열어서 유사한 증상/에러가 있는지 검색한다.

- 동일하거나 유사한 사례가 있으면 → 그 해결 방법을 먼저 시도
- 없으면 → 일반적인 디버깅 절차 진행

---

## 2단계: 디버깅 절차

1. 에러 메시지 전문을 읽고 원인 파악 (바로 수정 금지)
2. 원인을 나에게 한 줄로 설명
3. 해결 방법 제안 후 내가 OK 하면 수정
4. 같은 에러를 3번 이상 시도해도 해결 안 되면 → 나에게 보고하고 멈출 것
5. 이해하지 못한 수정은 하지 말 것

---

## 3단계: 해결 성공 시 — 이력 기록 판단

아래 기준 중 하나라도 해당하면 docs/troubleshooting.md에 즉시 기록한다.

**기록 기준:**
- 일반적이지 않은 방법으로 해결한 경우
- 3번 이상 시도 끝에 해결한 경우
- 환경/버전/OS 특이사항이 원인인 경우
- 나중에 또 만날 가능성이 있는 경우
- 공식 문서와 다른 방법이 필요했던 경우

단순한 오타, 명백한 문법 오류는 기록하지 않아도 됨.

---

## 4단계: 기록 형식

docs/troubleshooting.md에 아래 형식으로 추가한다.
파일이 없으면 자동 생성한다.

```markdown
### [YYYY-MM-DD] 문제 제목 (짧고 검색하기 좋게)

**환경**: OS, 언어, 프레임워크, 버전 등
**증상**: 어떤 에러/문제가 발생했는지 (에러 메시지 포함)
**원인**: 왜 발생했는지 (모르면 "미확인")
**해결 방법**:
(실제로 해결한 방법. 코드나 명령어가 있으면 코드블록으로)
**참고**: 관련 링크, 주의사항, 다음에 또 만나면 확인할 것
```
