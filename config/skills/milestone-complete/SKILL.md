# Milestone Complete Skill

마일스톤의 모든 원자 액션 구현이 완료되었을 때, 검증→최종산출물→승인 절차를 순서대로 수행한다.
이 절차를 건너뛰고 다음 마일스톤으로 진행하는 것은 금지다.

---

## 실행 조건

- 해당 마일스톤의 모든 원자 액션 코드가 작성 완료되었을 때
- 각 코드 변경이 `docs/진행내역.md`에 기록된 상태일 때
- 사용자가 마일스톤 완료를 선언하거나, 구현 루프 ③에서 자동 호출될 때

---

## 실행 절차

### 1단계: 사전 확인

1. `docs/설계서.md`를 읽는다
2. `docs/진행내역.md`를 읽는다
3. 완료 대상 마일스톤 번호를 확인한다 (M1, M2, M3 등)
4. **진행내역 기록 확인**: 해당 마일스톤의 모든 원자 액션에 대해 진행내역 변경 로그가 존재하는지 확인한다
   - 누락된 기록이 있으면 먼저 진행내역을 보완한 후 계속한다

### 2단계: 검증 체크리스트 실행

설계서 D섹션(검증 체크리스트)에서 해당 마일스톤의 항목을 순서대로 실행한다.

1. 각 검증 항목의 "검증 방법"을 실행한다
2. 결과를 기록한다: ✅ 통과 / ❌ 실패 / ⏸ 보류(외부 의존으로 실행 불가)
3. ⏸ 보류 항목이 있으면 `AskUserQuestion`으로 사용자에게 보류 사유를 설명하고 진행 여부를 확인한다
4. ❌ 실패 항목이 있으면 수정 후 재검증한다

검증 결과를 아래 형식으로 출력한다:

```
## M{N} 검증 결과

| # | 검증 항목 | 결과 | 비고 |
|---|---------|------|------|
| 1 | ... | ✅/❌/⏸ | ... |

### 통과: X/Y, 실패: X/Y, 보류: X/Y
```

### 3단계: 최종산출물 작성/갱신

1. `~/.claude/docs/deliverable-conventions.md`를 로드한다
2. `docs/최종산출물.md` 존재 여부 확인:
   - 없으면: deliverable-conventions.md 템플릿 기반으로 **첫 버전 작성**
   - 있으면: **현재 상태 기준으로 전체 재작성** (이전 버전과의 차이 표시 안 함)
3. 최종산출물에 포함할 내용:
   - 목적 (기획서 개요 기반)
   - 사용자 가이드 (설치, 실행, 사용법)
   - 폴더 구조 (실제 파일 시스템과 100% 일치)
   - 기능 목록 및 상태 (완료/진행중)
   - 파이프라인 (전체 동작 흐름)

### 4단계: 마일스톤 완료 승인

1. `AskUserQuestion`으로 사용자에게 마일스톤 완료 승인을 요청한다
   - 검증 결과 요약
   - 최종산출물 작성/갱신 완료 알림
   - 다음 마일스톤 안내
2. 승인 시: 다음 마일스톤 구현으로 진행
3. 거절 시: 거절 사유 확인 후 해당 단계로 돌아가 수정

---

## 주의사항

- 검증을 건너뛰고 최종산출물을 작성하지 않는다 — 반드시 2단계→3단계→4단계 순서
- 외부 API 키 등 사용자 의존성으로 검증 불가능한 항목은 ⏸ 보류 처리하되, 사용자 확인을 받는다
- 마지막 마일스톤 완료 시에는 CLAUDE.md §5 검증 의무도 함께 확인한다
- 이 스킬은 CLAUDE.md §4 구현 단계 실행 루프에 의해 자동 호출되어야 한다 — 사용자가 수동으로 호출하지 않아도 루프 ③에서 실행한다
