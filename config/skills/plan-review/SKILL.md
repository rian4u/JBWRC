# Plan Review Skill

기획서 초안이 완성되면 이 스킬을 실행하여 plan-conventions.md의 완성 조건을 검증한다.

---

## 실행 조건

- `docs/기획서.md` 파일이 존재할 때
- 사용자가 기획서 검토를 요청했거나, 기획서 초안 작성이 완료되었을 때

---

## 검증 절차

### 1단계: 지침 및 기획서 로드

1. `~/.claude/docs/plan-conventions.md`를 읽는다
2. `docs/기획서.md`를 읽는다
3. 기획서 완성 조건 표를 기준으로 검증을 시작한다

### 2단계: 11개 완성 조건 검증

각 항목을 순서대로 검증하고 결과를 기록한다.

| # | 검토 항목 | 검증 방법 |
|---|---------|---------|
| 1 | 목적·범위 | 개요 섹션에 배경·목적·성공 기준이 모두 있는가. 범위 섹션에 In/Out-scope가 있는가 |
| 2 | 분해 완전성 | 기능 계층 분해 섹션에서 모든 기능이 `[원자]` 태그가 붙은 리프 노드까지 분해되었는가 |
| 3 | Leaf Test | 각 `[원자]` 액션이 단일 행위자·단일 결과물·단일 책임·구현 가능성을 충족하는가. 위반 시 구체적 사유 기재 |
| 4 | 원자 액션 명세 | 모든 `[원자]` 액션에 입력·출력·기술 후보·마일스톤이 기재되어 있는가. 누락 항목 목록 |
| 5 | 벤치마크 완비 | 기술 선택지 섹션에 비교표가 있는가. 기술 리서치 결과에 조사 내용이 있는가. "추천" 항목에 근거가 있는가 |
| 6 | 역제안 완료 | 역제안 목록 섹션에 항목이 있는가. 각 항목에 결과(수용/거절)가 기록되어 있는가 |
| 7 | 요구사항 추적 | 요구사항 테이블의 모든 F-XX 번호가 기능 계층 분해의 원자 액션과 연결되는가. 연결 안 된 요구사항 목록 |
| 8 | 실현 가능성 | 제약사항 섹션의 내용과 원자 액션 간 충돌이 있는가 |
| 9 | 리스크 검토 | 리스크 섹션이 있는가. 대응 방안이 기재되어 있는가. 외부 API 의존, 환경 제약 등 간과된 리스크가 없는가 |
| 10 | 미확정 처리 | `[미확정]` 태그가 있는 항목에 결정 시점이 명시되어 있는가 |
| 11 | 사용자 승인 | (이 항목은 검토 후 AskUserQuestion으로 수행) |

### 3단계: 결과 보고

검증 결과를 아래 형식으로 출력한다:

```
## 기획서 검토 결과

| # | 항목 | 결과 | 비고 |
|---|------|------|------|
| 1 | 목적·범위 | ✅ 통과 / ❌ 미충족 | 구체적 사유 |
| 2 | 분해 완전성 | ... | ... |
| ... | ... | ... | ... |

### 통과: X/11
### 미충족 항목 조치 사항:
1. [항목 번호] — 구체적으로 무엇을 보완해야 하는지
2. ...
```

### 4단계: 미충족 항목 처리

- 미충족 항목이 있으면 해당 관심사(A~G)를 안내하고 보완을 제안한다
- 모든 항목이 통과하면 `AskUserQuestion`으로 사용자 승인을 요청한다
- 승인 후 `design-conventions.md`를 로드하여 설계서 작성 시작을 안내한다

---

## 주의사항

- 기획서가 없으면 실행하지 않고 기획서 작성부터 안내한다
- 검증은 기계적으로 수행하되, Leaf Test 위반 판단은 맥락을 고려한다
- 검증 결과를 수정하거나 조작하지 않는다 — 있는 그대로 보고한다
